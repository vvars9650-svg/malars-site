## Новый каталог

`test-frontend/specialization-catalog.js`: версия
`malars-specializations-2026-11-09-v1`. Шесть направлений, 39 подсистем.
Каждый прежний код включён ровно в одну подсистему, прежние подписи сохранены.
`MAL-SYS-*` и `MAL-SPEC-*` — исключительно внутренние идентификаторы UI МАЛАРС.
Исходный WORKS и API-справочники не изменяются. На первом уровне — шесть
направлений как заголовки с чекбоксами и короткими пояснениями. Сохранённые
старые mainCategories распознаются через исходный WORKS; неоднозначные EXT и SPEC
могут относиться к нескольким направлениям. При чтении исходные строки не
переписываются. Новые направления сохраняются в существующее поле mainCategories
как названия; схема API не меняется. Снятие направления — явное действие:
для старой смешанной категории сохраняются остальные выбранные направления.

Во втором разделе по умолчанию видны направления первого уровня и направления,
в которых уже есть сохранённые выборы. Остальные закрыты под спокойным
подзаголовком «Другие направления». Поиск ищет по всему справочнику; непустой
запрос отключает фильтр «Только выбранные», чтобы пропущенный профиль был доступен.
Выбор найденной подсистемы добавляет направление в mainCategories. Снятие
поиска не прячет только что добавленный профиль.

Внутренние коды МАЛАРС, версия каталога и технические пояснения о кодах скрыты
из видимого интерфейса; значения в данных и поисковом индексе не удаляются.
Старые строки компетенций на экране проверки и в блоке восстановления показаны
без кодовых префиксов. Нормативные марки РД остаются рядом с расшифровками.

Нормативные марки РД показаны отдельно от внутренних кодов и поисковых
сокращений. Основание: ГОСТ Р 21.101-2026, приложение В (рекомендуемое),

## Совместимость и ограничение сохранения

`validate_participant_draft()` принимает только фиксированный набор полей.
Новая вложенная структура подсистем и операций туда не входит; финальная
валидация признаёт только прежние WORK_CODES. API и backend не изменены.
Переименовывать коды или кодировать детализацию в `otherWorks` нельзя.

UI изменяет `answers.competencies` только для старых компетенций. При
восстановлении сохраняет исходную строку, даже если подпись отличается от
каталога; неизвестные значения также сохраняются до явного снятия выбора.
Новые специализации и операции НЕ включаются в сетевой payload. Их черновик
хранится в localStorage по версии каталога и intake ID, без токена и контактов.
На другом устройстве новая детализация не появится. При недоступности
localStorage показывается предупреждение о хранении только в памяти страницы.
Ограничение видно в редакторе, при проверке и на экране результата. Кнопка
перехода из раздела 2 сообщает «детализация локально».

Массовое применение работает по всем выбранным подсистемам, включая скрытые
поиском. Добавляет применимые операции без замены существующих; отчёт показывает
число добавленных связей и пропущенных неприменимых. Выбор операции выбирает
подсистему; снятие подсистемы явно снимает её специализации и операции.

## Сборка и проверка

`python backend/deploy/build_test_frontend.py` копирует два новых frontend-модуля
и включает их перед `participant-flow.js`. Изменение файла сборщика не меняет
API, облачную конфигурацию или runtime backend. Сборка сама ничего не публикует.

Локальная сборка на localhost:8765 имеет локальный API base URL. Существующий
preview-сервер хранит только локальные старые поля; его имитация отправки
не считается проверкой сохранения новой детализации в реальном API.

Проверки: `node --check` для frontend-модулей; локальный browser regression:
`node test-frontend/e2e/specializations.local.cjs`. Требуется установленный
`playwright` (можно указать NODE_PATH) и Chromium. При необходимости путь к
браузеру задаётся `PLAYWRIGHT_CHROMIUM_EXECUTABLE`. Тест работает только с
localhost, использует вымышленные данные и проверяет payload, восстановление,
поиск, массовое применение, мобильную ширину и положение чекбокса.

Проверка упрощённого интерфейса: профильные разделы по умолчанию, раскрытие других
направлений, глобальный поиск и добавление пропущенного профиля, шесть заголовков
на уровне 1, восстановление старых mainCategories и отсутствие видимых внутренних
кодов. Схема локального хранилища не менялась, детализация предыдущего просмотра
остаётся доступна.

Полный browser-сценарий также проверяет создание анкеты с выбором нового
направления «Электрика» на уровне 1. При этой проверке устранена гонка
loadCityOptions: загрузка городов ждёт malars:core-ready; кэш, полностью лишённый
кодов регионов, не используется. API и backend при этом не менялись.
Для уже запущенного изолированного Chromium тест поддерживает
PLAYWRIGHT_CDP_ENDPOINT=http://127.0.0.1:9226.

Для текущих принятых последовательных шагов, шести разделов и локальных проверок
приоритет имеет HANDOFF_LOCAL_PREVIEW_2026-11-09.md. Этот аудит описывает начальную
версию каталога. Тестовые контакты находятся только в локальном config вне Git.
